# S-Tier Eats 3.0 — "Social & Shareable" build plan

Status: planning (started 2026-10-13). iOS-first; Android 3.0 follows.

## Why 3.0
The app is feature-rich; the constraint is **growth + retention** (~4K iOS base, high
store conversion but low reach, tiny revenue). 3.0 must (1) look premium, (2) give
people something to **share** (growth loop), (3) lock in the backend cost + a real
monetization step so scaling doesn't hurt. Theme: **Social & Shareable**.

Decisions locked:
- **iOS-first, Android follows** (iOS already has the social/share foundation; Android's is a stub).
- **Foundation in scope:** flip `useFirestoreReads` + get affiliate live.
- Dish Photos (UGC) deferred to **3.1** (storage + moderation lift).

## Leverage already on iOS
`FriendActivityView`, `FriendCompareView`, `FriendTierView`, `InviteFriendButton`,
`MyStatsView`, and share-card rendering (`ShareableTierCard`, `NightOutShareCard` via
`ImageRenderer`). So iOS 3.0 mostly **extends + surfaces** existing pieces.
Android has NONE of this (friends = `friendsCommunityTiers` stub) → the Android follow
is a large social build.

## Workstreams

### A. Visual & brand refresh
- Display typeface for headers/tier labels (Trail Guide used Fraunces via NaturalType;
  decide: Fraunces for an editorial-dining feel vs a distinct face for S-Tier identity).
- Design-system tokens: one corner-radius scale (8/12/16/20), 8pt spacing grid, unified
  card + button styles, motion/haptics, refreshed onboarding + empty states.
- Optional: refined app icon (keep the tier-bars mark).
- iOS: new `DesignSystem.swift` (font/spacing/radius tokens) + font bundling in
  `project.yml`; apply across `TierComponents`, cards, `OnboardingView`.

### B. Shareable Lists / Collections (marquee, NEW)
- User lists ("Top 10 Tacos", "Date-night S-tier"): ordered restaurant IDs, title, emoji,
  public flag. Shareable as **image + deep link**.
- Firestore: `lists/{listId}` = {ownerId, title, emoji?, restaurantIds:[UUID], isPublic, createdAt, updatedAt}.
  Rules: owner write; public read when isPublic.
- Deep link: extend `onOpenURL` (today handles `tier/<id>`) to `list/<id>` -> ListView
  (universal link + `stier://list/<id>`).
- iOS: `RestaurantList` model, `ListsService` (Firestore CRUD), `ListsView` /
  `ListDetailView` / `ListEditView`, `ListShareCard` (ImageRenderer), entry point.
- Open: entry location (new tab vs Profile); public- vs private-by-default.

### C. Food "Wrapped" / shareable stats (extends MyStats)
- Recap card: top S picks, # ranked, visited count, top area, taste-match highlight,
  Foodie Rank -> **shareable image**. Seasonal "2026 in Food" framing optional.
- iOS: extend `MyStatsView` + new `StatsShareCard` (reuse card infra). Low-medium.
- Open: always-on "share my stats" vs a seasonal moment (or both).

### D. Social expansion (extends friends)
- iOS: richer **friend activity feed** (recent placements by followed users) +
  **taste-match leaderboard**. Surface on Community/home. Medium.
- Android: build friends end-to-end (follow graph, friend board, compare). Large — part
  of the Android 3.0 follow.

## Foundation (ships alongside)
- **Flip `useFirestoreReads` ON.** Verify consensus A/B first (admin "Rebuild consensus
  docs", compare Everyone board on/off), deploy `docs/firestore.rules`, then default the
  flag ON. The social reads add load -> lock the cheap per-restaurant consensus reads in.
- **Affiliate live.** Reapply OpenTable via the Dispatch property on Impact; add
  DoorDash/Uber Eats; wrap the existing reserve/order URLs with tracking params once
  approved (`openReserve` already deep-links — just swap to the tracked URL).

## Phasing (iOS 3.0)
0. Design system + typeface (makes everything read 3.0)
1. Shareable Lists (marquee)
2. Wrapped stats + Social expansion (reuse share + friend infra)
3. Flip Firestore reads + affiliate
4. QA pass (device + simulator — map/visual changes always get a device check) -> submit iOS 3.0
5. **Android 3.0 port** (friends from scratch + lists + wrapped + visual)

## Success metrics to watch
- Shares generated (lists / wrapped / tiers) and install referrals from shared links
- D7 retention lift; store-listing conversion after the visual refresh + new assets
- Affiliate revenue (reserve/order)

## Open decisions (resolve before building each)
1. Typeface: Fraunces vs a distinct S-Tier display face.
2. Lists entry point + default visibility.
3. Wrapped: always-on vs seasonal vs both.
4. New app icon or keep current.
